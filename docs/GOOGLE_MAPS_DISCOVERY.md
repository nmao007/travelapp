# Map and discovery pass — September 29, 2026

Explore now shows larger, icon-coded pins with visible names for selected nearby places, a fuller-color vector map, an explicit “Near me” action, and distance-based suggestions near the selected day plan. Searches appear as the traveler types; common searches can be started with one tap. A real place can be saved as an Idea or added to a suitable trip day without filling out a form. Multi-city discovery avoids automatically attaching a place in a different city to the currently selected day. The Trip dashboard now offers one-click nearby suggestions and a map preview of the next mapped stop. Names prefer sourced `name:en` labels and retain the local name when both exist; proper names without a sourced English label remain in their original language. No machine translation is claimed.

The default public map uses [OpenFreeMap's Liberty style](https://openfreemap.org/quick_start/) and OpenStreetMap points of interest. For a Google basemap, configure `GOOGLE_MAPS_BROWSER_KEY` and `GOOGLE_MAP_ID` on the server. The browser key is necessarily public: restrict it to this app's web origins and the Maps JavaScript API, enable billing, and use a map ID as described in [Google's key guide](https://developers.google.com/maps/documentation/javascript/get-api-key) and [Advanced Markers setup](https://developers.google.com/maps/documentation/javascript/advanced-markers/start). With both values present, the app selects Google Maps for its map surface and custom place pins. If the Google script fails, it falls back to OpenFreeMap. Google mode is code-complete but unverified against a live Google project because this workspace has no authorized Maps credentials. The application does not currently use Google Places, navigation, Street View, or booking APIs.

POI names and recommendations still come from OpenStreetMap, even over the optional Google basemap. There is no claim of Google-quality place coverage, reviews, hours, or routing. Google Places can only be added behind a provider-specific data and display policy: [Google's Places policies](https://developers.google.com/maps/documentation/places/web-service/policies) require a Google map when showing Places results on a map, and the [Maps service terms](https://cloud.google.com/maps-platform/terms/maps-service-terms) restrict use with non-Google maps and storage. A production integration also needs a company-owned account, billing limits, restricted server credentials, cost review, field masks, attribution, and tests. Its [Nearby Search](https://developers.google.com/maps/documentation/places/web-service/nearby-search) supports language selection but is billed according to requested fields.

These suggestions are grounded in source records and distance, not ratings, verified opening hours, predicted travel time, or personalization. Public Overpass and Photon endpoints remain prototype dependencies; a hosted, monitored POI/search service is needed for dependable release use. Flight status, reservation import, commercial booking, cross-device sync, and native apps are still separate unfinished product tracks.
