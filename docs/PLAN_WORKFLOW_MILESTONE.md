# Checkpoint — a place becomes a day plan

September 28, 2026. This slice repairs the gap between discovering a real place and building a usable day. [Wanderlog's itinerary guidance](https://wanderlog.com/blog/faq/) describes moving places between days, bulk actions and day-specific map views; [TripIt's current feature matrix](https://help.tripit.com/en/support/solutions/articles/103000063396-tripit-or-tripit-pro-) includes an organized itinerary and map. We are working toward those outcomes without copying either product's visual design or claiming their provider integrations.

The Plan screen now moves an unscheduled idea to the selected day in one tap. A traveler can move a flexible stop to another day or back to Ideas, reorder flexible stops with up/down controls, and reopen the trip to find the same order and provider-backed place identity. Timed items and reservations stay anchored to their confirmed day and clock time; changing those still requires opening the item. The map opens automatically on desktop when mapped places exist, plots the selected day's places together with saved ideas, and clicking a pin focuses the same plan item. The trip route is collapsed so daily planning stays the main focus.

Verified with 54 passing tests, type checking, a desktop browser flow using a sourced Lisbon place, a map pin, day move and reload. The map is a location view, not a travel-time or route promise. The guest workspace still has no cross-device sync. The next operational gap is per-city day assignment and travel between multiple destinations, followed by sourced travel-time estimates and reservation import. These should be finished before treating the planning flow as competitor-grade.
