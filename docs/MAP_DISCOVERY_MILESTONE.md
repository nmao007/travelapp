# Checkpoint — discover on the map, keep the plan coherent

September 28, 2026. This is a reviewable slice of the larger travel product, not feature parity or a release candidate. It builds on [day planning](PLAN_WORKFLOW_MILESTONE.md).

In Explore, a traveler can choose any trip destination, browse actual mapped points of interest by category, drag the map, and request places around the new center. Nearby results and already-saved trip places appear on the same map. Selecting a pin or result opens a compact detail card over the desktop map, with a direct action to add it to the selected day, save it as an Idea, or return to its existing Plan item. Sourced place IDs prevent duplicate trip items when the same place is encountered in search, nearby discovery and the itinerary. On provider failure, the last loaded results remain visible and are labeled as belonging to the previous center, with a retry action.

In Plan, mapped places can be viewed for the selected day, all trip days, or unscheduled Ideas. Switching views keeps the map mounted. Selecting a pin focuses the matching itinerary item and its day; selecting a list item focuses its pin. Fixed commitments retain their date and time, while flexible stops can still move between days and Ideas.

Checked in the desktop browser with a real Lisbon POI: map drag exposed “Search this area,” a new Overpass response displayed different nearby places, the saved pin stayed present, map layers changed without a reload indicator, and the browser console showed no errors. Type checking, the production build, and all 54 automated tests passed. Motion respects reduced-motion settings. The local guest workspace still does not sync across devices. The newer [map and discovery pass](GOOGLE_MAPS_DISCOVERY.md) adds labels, English-name preference, contextual suggestions, live search, and an optional Google Maps renderer.

Next, the map needs a production-grade POI service, sourced opening hours and place details, route distance/time geometry, and lodging/transport layers. The current public Overpass service can fail or respond slowly; the UI retains prior results but that does not satisfy production reliability. A trip with several cities also needs days tied explicitly to each city, rather than relying on a global date and a destination selector. Reservation import, flight status, in-app booking, and native iOS/Android delivery remain separate unfinished tracks.
